# Настройки источников и примеры для тестов

Здесь мы задаём, откуда скачивать списки и как проверять полученный фильтр.
Например, в `sources.json` перечислены источники, а в `controls.json` — тестовые
примеры: GitHub должен открываться, рекламный домен — блокироваться.
AdGuard эти JSON-файлы напрямую не читает.

| Файл | Что содержит и кто использует |
|---|---|
| `sources.json` | Какие списки скачивать и когда отвергать их как слишком старые, маленькие или большие. URL задаётся полями repository/ref/path; читает pipeline.load_config |
| `controls.json` | Небольшой набор тестовых доменов с ожидаемыми результатами: что должно проходить и что должно блокироваться. Не устанавливает разрешения или запреты в AdGuard |
| `public_suffix_list.dat` | Public Suffix List (PSL): общие окончания доменов вроде co.nz и github.io, которые нельзя блокировать целиком; читает blocklists.py |
| `public-suffix-source.json` | Откуда взят public_suffix_list.dat, по какой лицензии используется и какой должна быть его контрольная сумма SHA256 |

## controls.json — примеры для проверки, а не правила фильтра

В `allowed` перечислены домены, которые тест ожидает увидеть разрешёнными.
Например, `github.com` проверяет доступ к обычному сервису, а `pornhub.com` —
что категория взрослого контента не включилась случайно. Добавление имени
в `allowed` не разрешает его в AdGuard: если фильтр его запрещает, проверка
завершится ошибкой, а само правило блокировки останется на месте.

В `blocked` перечислены примеры ожидаемых блокировок по четырём категориям.
Например, запрос к `mc.yandex.ru` должен блокироваться как трекер. Добавление
имени в этот раздел тоже не создаёт блокировку — тест требует, чтобы она уже
следовала из настоящих правил фильтра.

`pipeline.py build` проверяет ожидания на собранных доменных правилах до записи
результата. `verify_adguard.py` отправляет настоящие DNS-запросы к выбранному
серверу и проверяет каждый домен отдельно по A и AAAA. Падение теста останавливает
соответствующую проверку; автоматического разрешения сайта или изменения сервера нет.

Это выборка для обнаружения типичных поломок, а не полный перечень сайтов.
Успешный DNS-запрос к главному домену не проверяет вход в аккаунт, видео,
картинки и другие ресурсы страницы. Реальные региональные правила находятся
в `regional/ru-cis/domains.csv`, исключения — в `regional/ru-cis/allowlist.csv`,
а все подключаемые правила — в `output/adguard/combined.txt`.

Поле `_description` внутри JSON содержит пояснения для читателя; сборщик и
DNS-проверка используют `allowed` и `blocked`. Строки с `#` или `//` как
комментарии недопустимы: эти файлы читаются стандартным JSON-парсером Python.

## Защита общих доменных платформ

Пример: правило на `github.io` отклоняется как запрет общей платформы,
а `project.github.io` может быть конкретным доменным правилом.

Проверка конфигурации: `python3 scripts/ru/pipeline.py validate` из корня.
Изменение источника или PSL требует проверки реального содержимого и тестов;
контрольную сумму нельзя обновлять лишь для подавления ошибки проверки.
