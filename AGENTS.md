# Работа с dns-blocklists-ru

## Назначение

Это публичный форк Mullvad для DNS-фильтрации с региональными дополнениями
России и СНГ. Владелец: `bakzalitdootvala`; основной репозиторий:
`bakzalitdootvala/dns-blocklists-ru`.

Пользовательские документы, комментарии и docstrings пишутся на русском.
Идентификаторы API, домены, пути, названия веток и исходные лицензии сохраняются.
Секреты, конфигурации клиентов VPN и сведения конкретного VPS в репозиторий не включаются.

## Ветки

- `maintainer` совпадает с официальным upstream `main` и не содержит наших коммитов.
- `main` содержит собственный сборщик, данные, документацию и готовые результаты.
- Новые изменения разрабатываются на актуальной основе, выбранной владельцем.

Автоматическая синхронизация `maintainer` допускает только fast-forward.
Расхождение истории останавливает обновление; force-push не используется.
Код upstream не исполняется и не сливается в пользовательскую ветку автоматически.

## Данные и категории

Разрешённый профиль: `adblock`, `privacy`, `malware`, `gambling`.
Категории `adult` и `social` не подключаются к итоговому DNS-фильтру.
Не блокировать страны, TLD, автономные системы или общие CDN по географии.

- `config/sources.json` задаёт источники, форматы и ограничения размера.
- `config/controls.json` содержит разрешённые и блокируемые контрольные домены.
- `regional/ru-cis/domains.csv` хранит доказательства и scope каждого дополнения.
- `scripts/ru/` содержит собственную реализацию.
- `output/adguard/combined.txt` — подключаемый DNS-фильтр.
- `output/threat-intel/` — IP/CIDR-источники для проверки DNS-ответов и их манифесты.

Не превращать точный домен в правило для всех поддоменов без основания.
Не удалять модификаторы браузерных правил ради получения DNS-правила.
Исключение одного hostname не должно разрешать весь родительский домен.
Дата загрузки или публикации не заменяет дату наблюдения вредоносной активности.
HaGeZi IP и Spamhaus IPv4/IPv6 обязательны для единого выпуска.
Проверять IPv6-сжатие, границы CIDR, A/AAAA и HTTPS hints в настоящих ответах
AdGuard. Общий IP может блокировать несколько сайтов; точное исключение
добавляется по проверенному сценарию, без разрешения всей родительской зоны.

## Пояснения и навигация

В каждом содержательном каталоге поддерживается README с ролью файлов,
входами, результатами, ограничениями и ссылками на связанные части проекта.
Исключение — `.github/`: описание каталога находится в `CONTENTS.md`.
GitHub выбирает `.github/README.md` раньше корневого README, поэтому такое имя
в `.github/` подменит главную страницу проекта.
Новые термины добавляются в `docs/GLOSSARY.md` с примером из этого репозитория.
Модули, классы и функции имеют русские docstrings; шапки shell-скриптов и
workflows объясняют запуск, зависимости, побочные действия и условия ошибки.
Названия workflow/job/step должны говорить, что именно проверяется или меняется.
При правке комментариев проверяйте, что исполняемая логика не изменилась.

## Проверки

Основная команда: `make check`.
Перед коммитом работают согласованные Ruff, тесты, проверка данных и Gitleaks.
Хуки не обходить; новые проверки согласовывать с владельцем.

Тесты должны проверять поведение, а не наличие строк исходного кода.
Изменение защитной проверки требует мутационного прогона: снять защиту,
увидеть падение соответствующего теста, вернуть защиту и получить зелёный результат.

Проверяйте источник, лицензию, размер, SHA256 и возраст входного снимка.
Пустой, повреждённый или устаревший источник не заменяет рабочий результат.
При изменении парсера проверяйте полный файл на живом AdGuard Home:
A/AAAA, exact/wildcard/suffix, обычные сайты, adult/social-контроли,
происхождение блокировки, загрузку и повторное обновление, память и время.
Старые фильтры не должны подменять доказательство работы нового фильтра.

## Публикация и обслуживание

Локальные commit/push выполняются только после согласования точного текста,
состава файлов, remote/ветки и проверенного аккаунта GitHub.
Отдельно согласованный workflow публикует только generated outputs
фиксированными сообщениями. Изменение его полномочий требует решения владельца.

Сохраняйте лицензионные уведомления поставщиков. Не выдавайте собственный
результат за официальный продукт Mullvad, AdGuard, HaGeZi или Spamhaus.

Проверки VPS выполняйте только по явной задаче владельца, прочитав его
серверные инструкции. Тестовые сервисы изолируйте на loopback, с отдельными
портами, данными и ограничениями ресурсов; после проверки остановите и уберите.
Не меняйте существующие службы, firewall и пользовательские исключения вне задачи.
