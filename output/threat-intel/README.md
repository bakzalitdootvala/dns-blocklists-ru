# IP-адреса и сети, из которых собираются блокировки

Здесь лежат проверенные списки IP HaGeZi и сетей Spamhaus. Наш сборщик
превращает их в правила `combined.txt`, чтобы AdGuard блокировал ответы
с этими адресами. CIDR в списках обозначает диапазон IP, а не один адрес.

`scripts/ru/threat_intel.py` создаёт списки и манифесты — файлы с датами, источниками
и контрольными суммами. `ip_inputs.py` читает их при общей сборке.
В AdGuard подключается готовый combined.txt, а не эти исходные IP-файлы.

| Файл | Роль |
|---|---|
| `hagezi-ipv4.txt` | Отдельные IP HaGeZi, из которых сборщик создаёт блокировки |
| `hagezi-manifest.json` | Отчёт о списке выше: версия, даты, SHA256, число адресов и отброшенные строки |
| `spamhaus-ipv4.txt` | Диапазоны IPv4 Spamhaus DROP, из которых сборщик создаёт блокировки |
| `spamhaus-ipv4-manifest.json` | Отчёт об IPv4: дата публикации, контрольные суммы исходника/результата, число сетей и расследований |
| `spamhaus-ipv6.txt` | Диапазоны IPv6 Spamhaus DROP для такой же проверки ответов IPv6 |
| `spamhaus-ipv6-manifest.json` | Отчёт об IPv6 с теми же сведениями, что в IPv4-манифесте |

TXT-файлы содержат адреса и сети. JSON-файлы нужны сборщику для проверки
их происхождения, свежести и целостности; сами по себе запреты не задают.

Все три источника обязательны для нового DNS-выпуска. Испорченный, слишком старый
или резко сократившийся набор останавливает сборку. Исторические региональные IP
лежат отдельно в `regional/ru-cis/` и сюда не подмешиваются.

Команды подготовки описаны в [BUILDING.md](../../BUILDING.md). До build-drop
исходные JSON должны пройти ClamAV. Уведомления Spamhaus нельзя удалять или
перелицензировать под GPL; правила firewall эти файлы не устанавливают.
