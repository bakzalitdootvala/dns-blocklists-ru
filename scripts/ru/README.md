# Наш сборщик фильтра AdGuard

Здесь наш Python-код: скачивает списки Mullvad, HaGeZi и Spamhaus, добавляет
региональные правила и собирает `output/adguard/combined.txt`. Здесь же находятся
проверки, которые обнаруживают повреждённые данные и неправильные блокировки.

Нужны Python 3.10+ со стандартной библиотекой, GitHub CLI `gh` для загрузки
и `dig` с проверенным бинарником AdGuard для живых DNS-тестов.
Настройки находятся в `config/`, дополнения — в `regional/ru-cis/`,
скачанные снимки — в `.cache/`, готовые файлы — в `output/`.

| Модуль | Что делает |
|---|---|
| `pipeline.py` | Управляет сборкой: скачивает доменные списки, добавляет наши правила и IP, записывает combined.txt и manifest.json. Команды refresh/validate/build |
| `blocklists.py` | Разбирает текст доменных правил, сохраняет их область действия (scope) и исключения, проверяет категории и общие суффиксы PSL. Помогает заменять файлы без частичной записи |
| `download_drop.py` | Скачивает два файла Spamhaus DROP. Повторно использует неизменённые локальные файлы в течение часа; антивирус ClamAV запускается отдельным шагом |
| `threat_intel.py` | Получает IP HaGeZi и подготавливает три сетевых списка с отчётами в output/threat-intel/ |
| `ip_inputs.py` | Проверяет, что все три IP-списка на месте, свежие и целые, затем передаёт их правила в pipeline.build |
| `ip_rules.py` | Превращает отдельный IP в правило `\|IP\|`, а CIDR-диапазон — в регулярное выражение (regex), которое узнаёт адрес внутри сети |
| `recent_threats.py` | Проверяет точные C2 из свежих отчётов и ограничивает применение 30 сутками от публикации |
| `expire_filter.py` | По timer снимает истёкшие блоки из установленного фильтра и кэша; проверяет DNS и откатывает обе копии при ошибке |
| `check_artifact.py` | Проверяет, совпадают ли SHA256, число и состав правил готового combined.txt с manifest.json |
| `sync_upstream.py` | Обновляет удалённую ветку maintainer до версии Mullvad через GitHub API; только fast-forward, то есть без переписывания истории |
| `verify_adguard.py` | Отправляет запросы A/AAAA уже работающему DNS-серверу и сверяет ответы с config/controls.json; при указании API проверяет источник блокировки |
| `test_ip_response.py` | Запускает отдельный AdGuard и тестовый DNS, проверяет блокировку IP в настоящих ответах, отключение/включение фильтра и уборку процессов |

## Последовательность данных

`refresh` и `refresh-ips` получают снимки, `download_drop` скачивает DROP.
После ClamAV команды build-ips/build-drop создают output/threat-intel/.
`pipeline.build` проверяет все входы, добавляет regional/ru-cis/ и пишет
output/adguard/. `check_artifact` сверяет байты; живой тест проверяет поведение.
Команды и зависимости: [BUILDING.md](../../BUILDING.md).

`sync_upstream.py` делает внешнюю запись GitHub. Остальные модули сами не
публикуют Git-коммиты. `test_ip_response.py` запускает собственные процессы и
останавливает их; `verify_adguard.py` только обращается к указанному сервису.
Для рабочего AdGuard со старыми hosts-фильтрами verify_adguard.py допускает
`--allow-loopback-blocks`: адреса 127.0.0.0/8 и ::1 считаются ответами блокировки
только для запрещённых имён. Обычные сайты с такими адресами проверку не проходят.
Без опции ожидаются нулевые 0.0.0.0 и ::.
Не запускайте загрузки, синхронизацию или полный build для проверки комментариев.
Локальная проверка разработки — `make check` из корня.
