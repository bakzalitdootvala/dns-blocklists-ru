# Тесты сборщика

Здесь тесты, проверяющие, что сборщик создаёт нужные правила и останавливается
на плохих данных. Например, повреждённый IP-список должен вызвать ошибку,
а готовый `combined.txt` при этом должен сохранить прежнее содержимое.

Запуск из корня: `python3 -m unittest discover -s tests -v` или `make test`.
Полная команда `make check` добавляет Ruff, проверку регионального каталога,
готового артефакта и Git diff. Unit-тесты не меняют VPS или GitHub: внешние вызовы
подменяются, файлы создаются во временных каталогах.

| Файл | Проверяемое поведение |
|---|---|
| `test_blocklists.py` | Правило блокирует нужное имя и не захватывает лишнее: exact/wildcard/suffix, общие суффиксы PSL, IDNA-имена, категории, исключения и минимумы |
| `test_build_integration.py` | Полная сборка по маленьким источникам, воспроизводимость, сохранение прежнего файла при ошибке |
| `test_pipeline.py` | Неверный SHA256, старая дата или неподтверждённое правило вызывают ошибку; исключения разрешают только точное имя |
| `test_ip_rules.py` | Регулярное выражение совпадает с IP внутри CIDR и не совпадает с адресом за границей; проверяются IPv4/IPv6 и границы строки |
| `test_ip_inputs.py` | Отсутствующий или повреждённый IP-список останавливает выпуск; повторная загрузка DROP в течение часа использует кэш |
| `test_threat_intel.py` | DROP содержит правильные записи, даты и лицензии; сети и расследования считаются без лишних повторов |
| `test_recent_threats.py` | Проверяет точные имена/IP, срок 30 суток, запрет подсетей и сохранение постоянных правил при снятии срока |
| `test_expire_filter.py` | Проверяет запись обеих копий, права и откат при ошибке перезапуска службы |
| `test_artifact.py` | Изменённый combined.txt не проходит сверку с SHA256, записанной в манифесте |
| `test_sync.py` | Ветка не обновляется принудительно (force), а результат записи подтверждается повторным чтением; настоящий GitHub не вызывается |
| `test_dns_verification.py` | Успешный ответ A не скрывает ошибку AAAA; проверяются отдельно ответы dig и код результата DNS (RCODE) |

Настоящий DNS проверяет отдельный `scripts/ru/test_ip_response.py`: он запускает
AdGuard и локальный источник ответов. Успех unit-тестов не заменяет такой прогон.
При тестировании защит намеренно нарушайте проверяемое условие, убеждайтесь,
что тест падает, затем восстанавливайте исходники и подтверждайте зелёный результат.
